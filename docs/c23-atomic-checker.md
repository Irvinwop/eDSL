# Checking finite atomic event graphs

Import `EDSL.Concurrency.C23Atomic.Check` to validate finite inputs for the
[C23 atomic-event fragment](c23-atomic-events.md). `check_sound` proves once
that a successful check satisfies the existing `Legal` contract. A new graph
supplies data and a successful computation instead of a separate proof for
every structural, coherence and predecessor condition.

The inputs describe an event graph. Certifying a program additionally requires
proving that its actual execution produces those events, values, objects and
read-from identities under the declared machine and OS assumptions.

## Input and certificate

`Table` contains an event list, one optional source index per event, and one
numeric modification rank per event. Both metadata lists must have the same
length as the event list. Read sources must select actual writes to the same
object with the observed value. Values validate the selected edge; they never
select or merge writers.

The second input is a square Boolean matrix on event indices. It is an
untrusted certificate containing sequencing and qualifying synchronization
edges. The checker verifies its dimensions, transitive closure and absence of
diagonal edges. A proved inclusion theorem places every actual happens-before
path in the checked relation.

Extra certificate edges are permitted when all remaining checks still hold.
They can make admission more restrictive. A missing required edge or a
malformed certificate is rejected; `false` alone does not prove the graph
semantically illegal.

For every certified edge on one object, the checker applies all relevant
write-write, read-read, read-write and write-read coherence conditions.
It separately checks no read from a modification ordered after it by HB and
requires each RMW to read the immediate preceding actual modification. Numeric
ranks may have gaps. Identical event records at separate indices remain distinct.

## Reusing soundness

This complete example admits an unchanged-value relaxed RMW between a release
and an acquire that observes it. Its modification ranks are deliberately sparse:

```lean
import EDSL.Concurrency.C23Atomic.Check
open EDSL.Concurrency.C23Atomic
open EDSL.Concurrency.C23Atomic.Check

def sample : Table Nat Nat where
  events := [⟨none, 0, .initialize 0⟩,
    ⟨some 11, 0, .store .release 7⟩,
    ⟨some 12, 0, .rmw .relaxed 7 7⟩,
    ⟨some 13, 0, .load .acquire 7⟩]
  sources := [none, none, some 1, some 2]
  ranks := [0, 7, 19, 0]

def relation : Matrix :=
  [[false, false, false, false],
   [false, false, false, true],
   [false, false, false, false],
   [false, false, false, false]]

example : Legal sample.toCandidate :=
  check_sound sample relation (by decide)
```

For routine admission, `certify table` proposes a transitive relation and runs
the same checker. `certify_sound table (by decide)` supplies legality when it
returns true. The proposal has no independent trust or completeness claim;
its output passes every certificate and graph condition.

`checkWellFormed`, `checkHappensBefore` and `checkConditions` expose the three
stages for diagnosis. The complete `check` requires all three. The certificate
can be generated by another tool: only the checked data and kernel-validated
soundness theorem establish admission.

## Scope and validation

The checker preserves the fragment's fully sequenced per-thread inputs and
synthetic initialization boundaries. It does not impose global chronological
RF or sequentially consistent latest-write behavior. The graph suite includes
relaxed store buffering and an allowed source graph whose read selects a
larger event-list index; the latter is not asserted realizable by x86-TSO.

The [regressions](../tests/C23AtomicCheck.lean) also cover a legal sparse-rank
unchanged RMW, stale payload after qualifying acquire, RMW source skipping,
identical writer records with different identities, missing synchronization,
out-of-domain RF and truncated metadata/certificates. Kernel evaluation checks
these supplied finite examples. The soundness theorem applies to arbitrary
finite inputs for which the check is proved successful.

The existing fragment exclusions remain: consume, SC, fences, nonatomics,
data-race semantics, source value/control computations and lifecycle HB are
outside this input model. Actual source/machine mapping, native runtime and
physical CPU correspondence remain separate obligations. This checker adds
no frozen compiler-function coverage.
