# Import a named ELF function

Run the existing importer on a named function anywhere in a complete ELF:

```sh
lake build edsl-cfg-import
lake exe edsl-cfg-import --elf-symbol function_name program.elf artifacts/Imported.lean
```

It generates and kernel-checks the complete literal file, exact requested name,
metadata witnesses and CFG. This replaces manual ELF metadata transcription.
It does not supply a functional specification or prove the function correct.
For an ordinary relative output such as `artifacts/Imported.lean`, declarations
use `EDSL.GeneratedCFG.artifacts.Imported`. Absolute outputs use their filename
stem. Distinct module paths coexist; use `--namespace MyProject.Routine` to
choose a stable suffix or distinguish absolute outputs with the same stem.
Suffix components must be simple ASCII identifiers; every component is
validated and quoted under the audited `EDSL.GeneratedCFG` prefix. Raw paths
and names cannot inject Lean source.

CLI names use UTF8 bytes; `ELF.FunctionCandidate.extract` and `extractWith`
also accept arbitrary nonempty NUL-free `List Byte` names.

## Select explicit static bounds

Named imports default to at most 64 function bytes and 32 instructions. Supply
both bounds when a complete function needs more space:

```sh
lake exe edsl-cfg-import --elf-symbol function_name --namespace MyProject.Routine \
  --max-bytes 96 --max-nodes 48 program.elf artifacts/Imported.lean
```

These options precede the two paths and may appear in any order. Each option
may occur once; missing values, zero, negative or nondecimal integers, duplicate
options, and profiles whose byte cap cannot satisfy the decoder's no-wrap
condition are usage errors. The namespace and profile options require
`--elf-symbol`; raw imports and the legacy `--elf SPAN_BYTES` mode retain their
existing behavior and limits.

The caller selects both static caps. Neither the file's declared size nor CFG
discovery chooses them. Increasing only the byte cap can still fail the node
cap. A cap never truncates a function at RET or omits its trailing bytes.
The emitted `observedProfile` records both chosen caps. Named-file checking,
`binding`, CFG discovery, `checked` and `valid` all use that same profile. See
[explicit ELF bounds](elf-function-bounds.md) for the library APIs.

Static caps do not increase execution fuel, proof-packet limits or kernel
budgets. `ELF.CallerResources` provides explicit-bound `With` helpers, and
`Corpus.Buffer.Certificate` carries the chosen bound through its loaded call
and named-file binding. `PureCall.ELFCertificate` currently retains the default
64-byte bound; its scalar example below uses the default import profile.

## Prove the independent behavior

Follow [Verify a new function](verify-a-function.md) and the
[complete doubling example](../EDSL/Examples/Verification/Double.lean). Import
the generated module through your Lean project's normal module path. Its
`EDSL.GeneratedCFG.artifacts.Imported` declarations provide:

- `observedProfile`, `observedBytes`, `observedGraph`, `checked`, `valid`: exact
  decoded code and the production CFG validity theorem under the selected
  profile. Reuse these directly with the matching VCG profile.
- `observedELF`, `observedName`, `observedInput`, `inputChecked`: complete-file,
  requested-name and declared-function-extent binding for an ELF certificate.
- `binding`, `loadedCode`: existing metadata/layout and abstract installed-code
  facts, without a dependency on the candidate parser or source emitter.

Define an independent `PureCall.Spec`: mathematical inputs, argument bindings,
domain, result relation and useful inputs. State a `VCGen.wp` theorem for those
inputs and the generated bytes/graph. `vcgen_run` composes finite steps;
`VCGen.Cutpoints.wp` and `vcgen_block` handle loops with client-supplied
invariants and a decreasing rank. Discharge the remaining mathematical and
access conditions. Keep checker results and desired executions out of admission.

Apply `pureCall_semantics_of_generated` to reuse every-AF execution, ABI,
complete RAM/permission frames and original caller-authority preservation.
The generated `LocalObligations`/`conditionalExecution` declarations are a
lower-level CFG interface; the VCG/PureCall route is the usual scalar workflow.
Buffers use the separate BufferCall adapter and explicit input loans.

For a scalar import using the default profile, bind the resulting `semantics`
theorem with the shared constructor:

```lean
open EDSL.GeneratedCFG.artifacts.Imported

def certificate : PureCall.ELFCertificate spec observedELF observedName :=
  PureCall.ELFCertificate.ofCaller spec observedInput inputChecked semantics
    caller fresh callerFacts separate value domain useful
```

The client supplies present caller mappings, freshness, code/stack separation
and a useful mathematical input. Current executable text, permissions,
ownership, lifetimes and OS resource facts remain explicit obligations. See
[ELF certificates](elf-certificates.md) and
[the full resource example](../EDSL/Examples/Verification/DoubleELF.lean).
No task registration, interpreter or new executable per program is required.

For an ordinary return slot, reuse `ELF.CallerResources.Stack.caller` and
`Stack.facts`. The latter keeps slot validity, canonical return/post-return
addresses and the post-return bound explicit. `Stack.check` checks disjointness
from each rounded LOAD page using intervals; `Stack.check_sound` proves the
existing `ELF.fresh` predicate without enumerating page bytes. Code/stack
separation remains a separate premise. `Stack.standard` is one useful modeled
witness; it does not restrict the universal semantic claim to those addresses.

The [named-import functional template](../tests/templates/NamedELFFunctional.lean)
shows this whole composition for the owned `twice` function. It imports the
generated `Named` module and reuses the independent mathematical doubling
specification. Its VCG theorem proves full64 modular doubling for every admitted
input; its ELF certificate uses the literal requested name. A concrete
`0xffffffffffffffff` call returns `0xfffffffffffffffe` at the actual modeled
return address with the original caller authority. The shared regression copies
the template to `generated/Functional.lean`, compiles it against that run's newly
imported ELF, and replays it with the combined generated-module closure. The
template is not a standalone Lake module: it deliberately needs the freshly
generated `Named` dependency.

## Scope and failure behavior

Every static and dynamic symbol table and its complete linked strings are
retained and checked by `ELF.FunctionInput.checkWith` under the selected cap.
A second requested-name
occurrence, even an undefined dynamic alias, rejects. No table, zero-size
inference or trailing function byte is silently dropped. CFG discovery checks
the complete declared extent against the existing production checker.

The current profile is ELF64 little-endian x86-64 ET_EXEC, at most 65,536 file
bytes and 16 program headers, ordinary section numbering, exactly one static
symbol table and at most one dynamic table. Selection requires one global
defined STT_FUNC, an RX PROGBITS section, consistent executable LOAD mapping,
and a nonzero complete declared extent. The byte and instruction caps default
to 64 and 32 respectively; named imports can select explicit caps as above.
The read-only CFG profile requires instruction/branch closure regardless of
the selected limits. Whole-file and metadata limits remain unchanged.

Sequential verification assumes stable ordinary RAM, absent asynchronous or
concurrent interference, supported canonical addresses and CET disabled.
Importing establishes no compiler preservation, native CPU correspondence,
relocation, OS startup or whole-kernel result. Unsupported instructions/effects
need a shared model extension; they are never lowered to a weaker contract.

Exit 2 means usage; 3 means unsupported profile/name/decoding; 4 means malformed
input; 5 means IO failure; 1 means generated kernel checking failed. Failure,
timeout and unsupported code establish no defect. A failed kernel check retains
candidate source for inspection; only exit 0 reports a checked import. The
command owns its kernel child's shared lock, so do not wrap it in an outer lock.
Emitted named imports use unchanged proof budgets for every static profile.

Run the focused real-ELF regression and fresh-kernel check with
`bash scripts/check-named-elf-import.sh`. It executes the independent parser and
return-slot regressions, imports two differently named functions together, checks
an explicit namespace override, and proves the independent functional/current-call
contract above. It also links a project-owned 68-byte assembly function: the
default profile rejects it, a larger byte cap alone still rejects its 34 nodes,
and explicit 68-byte/40-node admission succeeds. The
[profiled template](../tests/templates/ProfiledNamedELF.lean) checks the exact
complete text and an independent constant-result/continuation contract for a
concrete modeled loaded call. Mutating the selected suffix or the literal ELF
suffix beyond byte 64 rejects the stale generated proof even after an early RET.
The gate checks invalid and mixed-mode options and replays the combined positive
generated-module closure in a fresh kernel. It retains commands, actual statuses,
positive and synthetic negative results, plus closing source/frozen/provider/tool/
object pins under an ignored unique evidence directory. Compiler output must fit
the documented profile; the gate never executes native ELF code.
